# Unreal profiling: exactness proofs, engine-source facts and tooling traps

Companion to [native profiling](unreal-native-profiling.md) (one consuming Unreal 5.8.2 CL56702186 project on Windows; not reproduced in this repo). The method is in the profiling method (`phaser-verification` skill, agent-engine); measured costs are in [profiling measurements](unreal-native-profiling-measurements.md). Read an engine fact from the installed source before predicting a cost from it. Counts and timings are reported from one project; switch and counter names are placeholders.

## Exact versus behaviour-changing, and the shadow check

- [general] The class decides who approves: exact fixes ship on the right-sized bar in [native profiling](unreal-native-profiling.md); behaviour changes need the owner. Re-architecting existing game AI is not something to build process around.
- [general] Exact fixes were built as runtime switches (`-MyProto=pilot,hazfar,effects,memo` or `all`), off by default. With `-MyVerifyProto` each computes the original result beside the new one, compares bitwise and counts mismatches and comparisons into the scenario receipt; zero mismatches over zero comparisons proves nothing. One run checked millions of AI cells, far-rejects, effect transforms and memo hits with zero mismatches, and a 60 s verify run on each of several routes reported zero mismatches and zero violations.
- [general] Trajectory or file equality between two runs is not an exactness proof when runs are not bit-reproducible. A per-second trajectory CSV differed between repeats of the same unchanged headless build: the first difference was a 158.4 against 160.0 armor value at about 19 s of scenario clock. `-Deterministic -FPS=60` fixes the step and seed; it does not make the run reproducible. Prefer the side-by-side counters.
- [general] Non-exact ideas stay prototypes until the owner approves: a scenery animation skip beyond 200 m of the camera (far items hold their last pose) measured 7.23 ms against 7.19 without it in the combined run, no measurable gain. A cached hazard penalty field and a lower AI planning rate change paths and outcomes and were held back for review.
- [general] Measure fixes alone and combined on the worst scenes. The merged effect transform gave no gain headless; the AI loop hoist gave 3.2 ms; together the exact set took the heaviest scene from 13.06 to 7.18 ms rendered.

## Engine facts read from the installed 5.8.2 source

- [documented] `USceneComponent::SetWorldScale3D` converts to a relative scale and calls `SetRelativeScale3D`, which (when the value changed) calls `UpdateComponentToWorld`. That recomputes the component transform, propagates the update to attached children (`PropagateTransformUpdate`) and reaches `UPrimitiveComponent::OnUpdateTransform`, which updates the physics body scale. An unchanged scale is already skipped, so a per-frame scale on many pooled components pays this every time the value moves.
- [documented] `USceneComponent::OnVisibilityChanged` calls `MarkRenderStateDirty`, and so does `UStaticMeshComponent::SetStaticMesh`. Toggling visibility or meshes per frame marks render state dirty; count toggles (a project counter) instead of assuming they are free.
- [documented] `UPrimitiveComponent::SetCustomPrimitiveData*` writes only when the values changed and then calls `Scene->UpdateCustomPrimitiveData`, a cheaper path than a render-state recreate. Changing the default custom data marks render state dirty.
- [documented] `UActorComponent::ExecuteRegisterEvents` creates render state only when `FApp::CanEverRender()`. A `-nullrhi` run discards render data and never sends transforms to a scene, so it cannot measure render-side cost, and merging imported meshes through render data produced nothing headless. Pair every headless attribution with a rendered check.
- [documented] `UInstancedStaticMeshComponent` has `InstanceStartCullDistance`, `InstanceEndCullDistance` and `bUseGpuLodSelection` (`r.InstancedStaticMeshes.GpuLod`). Component-level draw distance tests the component's bounds, so a culled chunk must be smaller than the cull distance.
- [general] `ParallelFor` over game-thread work is only exact if each index reads an immutable snapshot and writes its own output slot, with no shared accumulator or random stream. The project did not use it; apply the exact-proof counters before shipping one.

## Measure on a quiet machine

- [general] Other editors, commandlets or games on the same machine share CPU, GPU and memory with the run being measured. A receipt recorded beside them can look like a regression in the game. Record the count of other Unreal processes and the free physical memory in every capture and profiling receipt, before the run and again after it, because another editor can start mid-run.
- [general] Wait a bounded time for the other processes to leave, then refuse to record unless contention is allowed explicitly. A receipt recorded with the allow flag keeps `contended: true`; a budget comparison rejects a contended receipt or one with no block.
- [tested] Helper: [editor contention](../../../examples/unreal/contention/README.md) (`wait`, `sample`, `verify`, and `waitForQuiet` / `stampReceipt` / `judgeReceipt` for scripts). It lists processes through a hidden PowerShell call, counts `UnrealEditor*.exe`, `UnrealEditor-Cmd.exe` and the game executables you name, leaves out your own process tree and any scratch project you name, and writes `{otherUnrealProcesses, freeMemoryMB, contended, reasons}` into the receipt.
- [tested] On 5.8.2 a headless `UnrealEditor-Cmd.exe -nullrhi` editor in a near-empty project held about 3 GB of working set, so each one removes that much free memory. The default floor is 4096 MB.
- [tested] A fixed CPU-only workload timed beside one and two idle or busy headless editors moved by a few percent at the median and more in the tail (p95 and max); the helper flagged every such phase. A rendering editor or game also shares the GPU; that case was not measured.
- [general] Contention from builds, cooks and shader compilation is not detected; run those before the measurement, not during it.

## Tooling traps

- [general] Unreal Insights tracing works on a Development build: `-trace=cpu,frame,counters,bookmark,region,log` (add `gpu` for rendered) with `-tracefile=` and `-statnamedevents`. A Test-configuration build cannot be taken on this engine distribution; UBT reports "Targets cannot be built in the Test configuration with this engine distribution". Trace Development and measure the overhead against untraced runs (5 to 8%).
- [general] Bracket the measured part of a run with a trace region (begun after the sampler warm-up) so the export covers only that part. Export headlessly with `UnrealInsights.exe -OpenTraceFile=... -NoUI -AutoQuit -ExecOnAnalysisCompleteCmd="@=export.rsp"` and `TimingInsights.ExportTimerStatistics ... -region=<name>` (seconds per timer; a mean per frame is a timer's inclusive time over the call count of `FEngineLoop::Tick`). It has no percentile column: a p95 or maximum needs `ExportTimingEvents` with `-columns` including `Duration` ([capture and export steps](unreal-native-insights-capture.md)). Delete the trace after export unless asked to keep it: a rendered trace can be about 2 GB.
- [general] Use trace counters for work the timers cannot express (items touched: transform calls, live effects, AI hazard cells, visibility toggles, suspension traces) and name scopes `Project/<Area>/<What>` so one filter selects them.
- [general] Contamination seen in this investigation: the first headless batch was thrown away, the owner reclaimed the GPU during a rendered window, and building a package while a benchmark ran disturbed both. Ask for a GPU window, run one rendered run at a time, never build during a matrix, and log why a run was discarded.
- [general] PowerShell: `-Routes 0 6` binds 6 to the next positional parameter; pass `-Routes 0,6`. Git Bash may not run `.ps1` under the default execution policy; use PowerShell. One edit transport lost literal backslash-n in here-string/heredoc edits; writing edit scripts to a file avoided that problem. Windows long paths need a `\\?\` prefix to delete.
- [general] Check free disk before each run (about 12 GB guard), because traces are large (a rendered trace is about 2 GB), and write one log line per run so an unattended night can be audited afterwards.
