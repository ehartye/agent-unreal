# MVVM and widget animation from a script

Target: Unreal Engine 5.8 on Windows. Everything marked tested was run on 2026-10-30 by the probe's `animation` and `mvvm` groups ([the probe](../../../examples/unreal/umg/README.md)), in a rendering editor started with `-RenderOffScreen -unattended` in a throwaway project with Epic's MCP, AllToolsets, UMG and MVVM toolset plugins enabled, through the server and session in [Scripting a widget](unreal-umg-script-widget.md). The runs are named A-Q1 run 1 to 3 (animation) and A-Q2 run 1 to 3 (MVVM); each probe invocation answered both questions.

## Bind a view model to a text block (MVVM)

- [tested] A-Q2 run 3, 2026-10-30: the MVVM toolset's own tools made a view model with a text property, put it on a Widget Blueprint holding a text block named `ProbeText` and bound the property to the block's `Text`. `ListWidgetViewBindings` returned the binding (source `ScoreText` of the view model class, destination `Text` of `ProbeText`, `OneWayToDestination`, no conversion), `CompileWidgetBlueprint` returned true, and a fresh editor loaded the saved Widget Blueprint with the binding present and the view model listed. Three runs were used; runs 1 and 2 ended in refusals, below.
- [tested] A-Q2 run 3, the calls in the order they ran, each with the arguments `describe_toolset` lists: `CreateViewModel` (`viewModelName`, `packagePath`, `parentClass` `{"refPath": "/Script/ModelViewViewModel.MVVMViewModelBase"}`); `AddViewModelProperty` (`viewModel`, `propertyName`, `propertyType` `"text"`, `defaultValue`, all required); `AddViewModelToWidget` (`widgetBlueprint`, `viewModelClass` as the generated `_C` class); `CreateViewBinding` (`widgetBlueprint`, `sourceContext` the `_C` class, `sourcePropertyPath`, `destinationContext` the text block reference, `destinationPropertyPath` `"Text"`, `conversionName` `""`), which was refused; `BlueprintTools.compile_blueprint` of the view model blueprint; `CreateViewBinding` again, which returned the binding; the three `List` tools; `CompileWidgetBlueprint`; `AssetTools.save_assets` of both assets. Compiling before `AddViewModelToWidget` is the unit-tested order, not one that ran.
- [tested] A-Q2 run 3: the view model blueprint must be compiled before the binding is created. Without it `CreateViewBinding` was refused: `Failed to create view binding. Invalid property path 'ScoreText'. Property does not exist in 'VM_ProbeScore_C'`. The scripted run failed at that step and was repaired by hand in a hold session (the probe's `--hold`: one call at a time in an open editor): compile, then `CreateViewBinding` again returned the binding GUID. The corrected chain, which compiles the view model blueprint before `AddViewModelToWidget`, is unit-tested against a fake editor but was not re-run end to end, because the cap of three runs was used. The hand repair compiled after `AddViewModelToWidget`.
- [tested] A-Q2 runs 1 and 2, refusals word for word: `AddViewModelProperty` without `defaultValue`: `Function "AddViewModelProperty", input param "defaultValue" is required by the function input schema Json, but is missing from the incoming function input params Json.`; `AddViewModelToWidget` with the asset path instead of the `_C` class: `Parameter error: /Game/UI/VM_ProbeScore.VM_ProbeScore is not valid Class for property 'ViewModelClass'.`; `CreateViewBinding` without `conversionName`: `Function "CreateViewBinding", input param "conversionName" is required by the function input schema Json, but is missing from the incoming function input params Json.` Its description calls `conversionName` optional; the schema requires it.
- [tested] A-Q2 run 1: `ListViewModels` takes a `searchPath`. A-Q2 run 2: the view model on the widget survived a save and a fresh editor.

## Widget animation: no route found

- [tested] A-Q1 runs 1 to 3, 2026-10-30, invalidated: no tool adds a track and a key to a widget animation of a saved Widget Blueprint, and none creates one that persists. Routes tried and their messages: the eight `animation_toolset.*` toolsets were described and none names a widget (the UMG toolset's 23 tools include no animation tool); editor Python made the objects (`unreal.new_object` of `WidgetAnimation` inside the blueprint and of `MovieScene` inside it) but `animation.set_editor_property('movie_scene')` raised `Failed to find property 'movie_scene' for attribute 'movie_scene' on 'WidgetAnimation'` and `blueprint.set_editor_property('animations')` raised `Property 'Animations' for attribute 'animations' on 'WidgetBlueprint' is protected and cannot be set` (also not readable); `ToolsetLibrary.set_object_properties` returned False for both, and the object tool `set_properties` answered `the following properties could not be set: MovieScene` and `... Animations`; `add_track_to_sequence` and `get_bindings` answered `... :ProbeFade is not valid LevelSequence for property 'sequence'.`; `add_track_to_binding` with an empty binding answered `Failed to add track of type '... MovieSceneFloatTrack ...' to binding.`; the 14 other Widget Blueprints in engine and plugin content hold no animation to duplicate. A fresh editor read back `animations []`, no track, no key. Next experiment: an editor C++ function (a bridge, not built here) that assigns the movie scene and registers the animation on the blueprint, then try `add_track_to_binding`, `set_property_name_and_path`, `add_section` and `add_key_float` on it. Those four take a track, a section or a `MovieSceneSequence`-typed binding, so they might accept a widget animation; that was not run.

- [tested] A-Q1 runs 1 to 3: a widget animation was never authored; the C++ route above was not built or run.
