# Unreal import helper in a game with a regenerated project

How a game that rebuilds its content project every run, and that also writes its own `/Game/...` folders, adopts the [guarded import helper](unreal-import-reuse.md) and its [per-mesh policy](unreal-import-policy.md).

- [general] The receipt, lock and pending journals live under the project's `Saved/AgentEngineImports/` and the outputs under `Content/Generated/<folder>`. A game that deletes and regenerates its content-bake project every run loses both, so `--if-changed` never reuses there; the identity also contains the project path and the project's `Config`, `Binaries` and `Plugins` files. In such a game the policy and read-back still work (default or `--force`, one Editor launch of about 16 seconds per destination), but reuse does not. There is no `receiptRoot` or stable-identity override: moving only the receipt would be useless without also restoring the outputs and removing the project path from the identity, which is a redesign. It is a backlog item, not a hidden option.
- [general] To keep reuse, run the helper in a persistent project that is not regenerated (an import-cache project beside the repository), then have the bake copy or cook from its `Content/Generated/<folder>` packages. That copy step is not implemented or verified: copied packages keep their `/Game/...` paths and resolve a referenced material such as `/Game/Art/M_Ink` only if the target project contains it.
- [general] Coexistence with game-owned folders. The helper owns every file under its one `/Game/Generated/<folder>` destination, including `_Import/Pipeline`, and never writes elsewhere, so a game that also writes `/Game/Props` is not disturbed. The consequence is that the helper's meshes live at `/Game/Generated/<folder>/<asset>`: update references, or copy them with the game's own script. Moving or deleting files inside the owned folder is an owner edit and produces `OUTPUT_CONFLICT`. The helper needs the project closed, so it cannot be called from inside the game's own Editor bake; run it as a separate step before the bake opens the project.
